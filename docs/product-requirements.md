# Miles Dance Studio — погоджені продуктові вимоги

## Призначення

Внутрішня mobile-first вебадмінка для щоденної роботи Miles Dance Studio. Система об'єднує клієнтів, викладачів, напрямки, групи, регулярний розклад, заняття, абонементи, відвідування, платежі, додаткові збори, оренду та статистику.

Майбутній публічний сайт і клієнтський портал не входять до поточного релізу, але для них зарезервовано домен `miles.wtmelon.store`.

## Домени

- `admin-miles.wtmelon.store` — адмінка.
- `api-miles.wtmelon.store` — API.
- `miles.wtmelon.store` — майбутній сайт і клієнтський портал.

## Користувачі та ролі

### OWNER

- Усі операційні можливості адміністратора.
- Повна фінансова аналітика.
- Керування користувачами, ролями та дозволами.
- Керування тарифами, продуктами й системними налаштуваннями.
- Скасування підтверджених платежів із обов'язковою причиною.
- Налаштування Telegram-бота.
- Перегляд стрічки активності та повного журналу аудиту через API.

### ADMIN

- Клієнти, викладачі, напрямки, групи й розклад.
- Продаж абонементів та реєстрація платежів.
- Відвідування «Був / Не був».
- Індивідуальні заняття, оренда, зйомки та додаткові збори.
- Перегляд статусу оплати конкретного клієнта.
- Без доступу до повної фінансової статистики, секретів Telegram і керування ролями.
- Не може видалити або переписати підтверджену фінансову операцію.

Викладачі в поточній версії є керованими сутностями без власного входу. RBAC має бути розширюваним, щоб у майбутньому додати нові ролі.

## Абонементи

- Підтримуються разові заняття, пакети на 4/15 і 8/30 та спільні абонементи для вибраних напрямків, груп або викладачів.
- Строк рахується включно: абонемент на 15 календарних днів із початком 1 серпня чинний до кінця 15 серпня.
- Статус «Скоро завершиться» вмикається, коли до завершення лишилося не більше 3 календарних днів.
- Одне підтверджене відвідування списує рівно одне заняття.
- Повторне натискання не створює повторного списання.
- «Не був» не списує заняття і не продовжує строк.
- Після завершення строку зберігається кількість занять, що згоріли.
- Система явно показує, з якого придатного абонемента буде списання.

## Календар і зал

- Повноцінні режими місяця, тижня та дня з переходом до вибраної дати.
- Групові, індивідуальні, оренда, зйомка та інші події.
- Регулярний розклад створює майбутні екземпляри занять.
- Активні події не можуть перетинатися в одному залі.
- Скасування не видаляє подію, фіксує причину, звільняє час і повертає помилково списані відвідування.
- Для проведеного заняття фіксується присутність викладача; дані входять до персональної статистики.

## Фінанси

- Готівка та картка/термінал.
- Категорії: абонемент, разове, персональне, оренда, світло, зйомка, інше.
- Статистика використовує дату фактичної оплати.
- Підтверджені платежі не редагуються і не видаляються фізично.
- OWNER може лише скасувати платіж із причиною; оригінал і скасування лишаються в історії.
- Прайс і параметри продуктів редагуються в адмінці, а не зашиваються в код.
- Кожен платіж зберігає адміністратора, який його прийняв, а за можливості — викладача; обидва зрізи доступні власниці.

## Сповіщення та активність

- В адмінці є центр непрочитаних сповіщень і окрема стрічка останніх дій.
- Система автоматично попереджає про завершення абонемента за 3 дні та про завершений абонемент.
- Успішні й невдалі платежі створюють окремі сповіщення.
- Після явної згоди користувача ці події надсилаються як браузерні Web Push навіть коли адмінка закрита.
- Кожен користувач має профіль у правому верхньому куті та може змінити пароль у будь-який момент без блокування першого входу.

## Telegram

- Токен бота задається в адмінці лише власницею.
- Значення маскується у UI та шифрується перед записом у БД.
- Master key зберігається тільки в environment production.
- Доступні перевірка токена, тестове повідомлення, заміна та видалення.
- У картці клієнта зберігається Telegram chat ID.
- Після скасування групового заняття бот автоматично повідомляє всіх учасників із заповненим chat ID; збій Telegram не відкочує саме скасування.
- Журнал відправлень містить статус і безпечний текст помилки без секретів.

## Дані

- Початковий seed містить викладачів, напрямки, групи, розклад, прайс і продукти з оригінального ТЗ.
- Seed містить правдоподібних клієнтів та операційні записи для перевірки інтерфейсу.
- У UI ці записи не маркуються як mock/test.
- Усі довідникові та операційні дані можна змінити через адмінку відповідно до дозволів.

## Production Definition of Done

- Увесь стек запускається однією командою Docker Compose.
- База мігрується й початково наповнюється автоматично та ідемпотентно.
- API має health/readiness endpoints.
- Адмінка і API працюють через HTTPS на погоджених доменах.
- Секрети відсутні в Git та образах.
- Критичні бізнес-правила покриті автоматичними тестами.
- Основні робочі сценарії перевірені на телефонному й desktop viewport.
- Production deployment ізольований в окремому Coolify-проєкті Miles Dance Studio.
